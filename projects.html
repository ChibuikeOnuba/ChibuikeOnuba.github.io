  1. Probe

    AI agents, LLMs, web automation

    Write a task in one sentence and get back a finished help center article, with exact steps and a screenshot for each one.

    See the live site
    More details

    The problem. Help center articles take a long time to write by hand, and they go out of date every time the app changes.

    How it works. You give Probe your app's address, a test login, and a goal in plain English. It maps the app's screens, including tabs and dialogs, then walks through the task with test data. It drafts numbered steps with exact button names and a screenshot for each step, and asks you about anything it couldn't see.

    Safety. It stops before irreversible actions such as delete, send, or invite, and runs on your own machine. Only screenshots go to the AI model.

    Keeping articles current. After an app change, a rescan re-describes only new or changed screens. Approved articles export as Markdown, rich text, or a zip with images, and can be translated, with translations flagged when a newer version is approved.

    Status. Working prototype.

  2. ETL Pipeline Silent Failure Detection

    Python, Streamlit, data quality monitoring

    Catches the pipeline failures that don't throw errors: the run finishes, but the data is wrong.

    View on GitHub
    More details

    The problem. Loud failures crash and get fixed. Silent failures finish successfully and quietly pass bad data downstream.

    How it works. A multi-stage pipeline (ingest, enrich, transform, aggregate) runs on the Olist e-commerce dataset of 99,441 orders. It runs twice: once clean as a baseline, and once with a failure injected at the stage where it would realistically start. A detection engine then compares every column at every stage.

    What it catches. Seven failure types: dropped records, stale timestamps, null floods, price corruption, duplicates, schema drift, and canary removal. On a clean pipeline it runs 98 checks covering row counts, null rates, distributions, timestamp freshness, canary records, cross-stage leakage, and category drift.

    Limits and next steps. Today it uses a single-run baseline and fixed thresholds. Version 2 plans a rolling baseline, dynamic thresholds, and ML-based anomaly detection.

  5. askDB

    Python, LangChain, GPT-4o-mini, MySQL, Streamlit

    Ask your database questions in plain English and get answers, without writing SQL.

    View on GitHub
    More details

    The problem. Most people who need answers from a database can't write SQL.

    How it works. You ask a question in a Streamlit app. LangChain sends it to GPT-4o-mini along with the table schema and three sample rows per table, and the model writes one SQL query. You can review and edit the SQL before it runs against MySQL. The result goes back to the model, which explains it in plain English.

    Limits and next steps. It works best for single-value answers, and since generated SQL runs without a guardrail, it should connect with a read-only database user. Measuring SQL accuracy on a fixed set of test questions is next on the roadmap.
